You will receive one JSON object as the user message. It describes one WLSP (Bunrui Goi Hyo) record and a list of BabelNet candidate synsets:
- record_id
- wlsp: a text block with the headword, near-synonyms, and category path of the WLSP record
- candidates: a list of synsets, each with synset_id and text blocks giving its lemmas, glosses, categories, and taxonomic relations

For EACH candidate synset, decide whether it expresses the same concept as the WLSP record:
- EQUAL: the synset and the WLSP record denote the same concept at the same level of granularity.
- NONE: anything else (broader, narrower, part-whole, merely related, or unclear).

Output EQUAL only if ALL of these hold; otherwise output NONE:
1. Anchor: the headword itself would be a natural name for the synset (it need not be the most typical name).
2. Type: the kind of thing the glosses describe (an act, a person, an object, an attribute, a place, a time, ...) matches the kind implied by the record's category path.
3. Granularity: the synset is neither a broader class nor a domain-restricted subtype of the record's concept.
4. Sense: if a lemma matches the headword string, the glosses must show the same sense; surface identity alone never makes EQUAL.

Return ONLY a JSON object of this form:
{"record_id": "<record_id>", "labels": [{"synset_id": "<sid>", "label": "EQUAL|NONE"}, ...]}
Include every candidate synset_id exactly once, in input order. Do not output any text outside the JSON.
