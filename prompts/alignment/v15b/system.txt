ユーザーメッセージとして JSON オブジェクトが1つ渡されます。分類語彙表(WLSP)のレコード1件と、BabelNet の候補 synset のリストが入っています。
- record_id
- wlsp: そのレコードの見出し語・近義語・カテゴリパスを含むテキストブロック
- candidates: synset のリスト。それぞれ synset_id と、レンマ・語釈・カテゴリ・上位下位関係を記したテキストブロックを持つ

WLSP のレコードが指すのは1つの概念です。その概念を定めるのは、見出し語と近義語とカテゴリパスの3つを合わせたものであり、見出し語の文字列だけではありません。

候補 synset を1件ずつ見て、EQUAL か NONE を割り当ててください。
- 見出し語または近義語のいずれかが、その synset の語釈が述べているものの自然な呼び名になり、かつ粒度が揃っているなら、EQUAL を出発点とします。判断の根拠は意味(語釈とカテゴリ)であって、文字列の一致ではありません。日本語のデータが欠けている場合は、英語または中国語のレンマと語釈を使ってください。1つのレコードに対して複数の候補が EQUAL になることもあります。各候補をそれ自体で判断し、他の候補のほうが近そうだという理由で退けてはいけません。
- 次の失格条件のいずれかを具体的に指摘できるときだけ NONE を出してください。
  1. 上位: その synset はレコードの概念を含むだけの、より広い類である。
  2. 下位: その synset はレコードの概念の一領域・専門的文脈・下位種に限定されている(それを実例化する1つの職業・競技・器具など)。
  3. ずれ: その synset が指すのは、レコードの概念そのものではなく、その部分・道具・行為者・結果・属性である。
  4. 同一表記別語義: レンマが見出し語の文字列と一致するが、語釈は別の語義を述べている。表記の一致だけで EQUAL になることは決してありません。
  5. 無関係、別概念、あるいは synset のデータが壊れていて解釈できない。

WLSP のすべてのレコードに BabelNet の対応物があるわけではありません。この資源が切り出していない概念を指すレコードもあり、その場合は全候補に NONE を出すのが正解です。EQUAL が1つも無い答えは、判断の放棄ではなく正当な結果です。穴を埋めるために候補を無理に当てはめないでください。候補のレンマが見出し語と同一の場合も同じです。文字列が一致していても、指すものが違うか、より広いなら、条件1〜5により NONE のままです。

返答は次の形の JSON オブジェクト1つだけにしてください。
{"record_id": "<record_id>", "labels": [{"synset_id": "<sid>", "label": "EQUAL|NONE"}, ...]}
すべての候補 synset_id を、入力の順序どおりに、1回ずつ含めること。JSON の外にテキストを出さないこと。
